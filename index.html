你把表的结构、字段、菜单写进一张 Excel，平台就帮你把「列表 + 新建/编辑表单 + 筛选 + 排序 + 导出 + 统计 + 图表」这一整套后台模块生成出来。

01 · SDP 是什么 & 给谁用

SDP（敏捷开发平台）解决的是一件很具体的事：让「重复的 CRUD 模板代码」消失。

一个中小型的普通 MIS 系统，真正的业务逻辑往往不到 20%，剩下 80% 是：

  • 一遍又一遍地搭列表页：筛选、排序、分页、导出
  • 一遍又一遍地搭表单页：各种输入控件、校验、只读控制
  • 一遍又一遍地搭工具栏：新增、编辑、删除、批量操作
  • 一遍又一遍地搭统计：维度表、图表、视图设置

SDP 把这 80% 的工作抽到了 Excel 配置里，开发者只需要关注真正属于业务的代码。

它适合谁？

需求 / 设计人员
在 Excel 里把表结构想清楚，就能产出一个可运行的原型模块，而不是只能画几张图
前端开发者
不用再从零搭表格、表单、筛选这些「长得都差不多」的页面
后端开发者
表结构即接口，数据字典即权限，字段定义即校验规则
小团队 / 中小企业
不用专门养一支前端，业务就能跑起来
💡 一句话总结：把「配置」还给业务，把「代码」留给真正重要的地方。

04 · 一个动作，两个产出 —— SDP 真正的杀手锏

如果只让你记住一件事，记住这条：SDP 不只是「开发快」，而是「系统 + 文档 + 客户认知」三件事一起搞定。

4.1 系统能跑，Word 文档也同时出

你花一份时间写 Excel，平台同时给你两样东西：

  • ✅ 一个能跑的系统
  • ✅ 一份对应的 Word 文档（设计文档 / PRD / 模块说明）

它们绑在一起出，因为都从同一个 Excel 数据源生成。

为什么要强调这件事？大多数团队都有这个痛：

  • 系统改到 v3 了，设计文档还是 v1 的
  • 字段加了一堆，旧文档没人同步，新同事看不懂
  • 客户问「这个字段什么意思」，翻遍代码也找不到
  • 每次系统上线，文档得有人单独再写一遍
💡 SDP 让文档跟系统永远对得上 —— 因为你不用「写两遍」。你只写了 Excel，平台把系统跑出来、把文档也生成出来，改 Excel 一次，两边同步更新。

4.2 需求会上就能 demo 给客户

以前：几轮下来，合同还没签
  • 客户说需求
  • 你回去画原型、写文档
  • 几天后给客户看 demo
  • 客户说「这不是我要的」
  • 你回去改，几天后再 demo
现在：同一个会上就签字
  1. 客户说完需求，你现场把字段写在 Excel 里（10 分钟）
  2. 上传到平台 → 系统当场能跑
  3. 给客户演示，客户当场提意见：「这个字段不要，加那个」
  4. 你现场改 Excel，5 分钟后再次 demo
  5. PRD 在 Excel 里，系统在浏览器里 —— 客户一边签字一边看效果
🎯 客户离开会议室的时候，看到的就是最终系统，而不是「之后会做的」。需求变更成本从「几天」降到「几分钟」。

05 · 三步开始用

想立刻把平台跑起来，跟着「快速开始」走一遍就够了，大概 30 分钟内能搞定。

01
装环境
nodejs 24.14.0 或更高版本
包管理器 yarn / npm / pnpm 任选一个，推荐 yarn
02
跑起来
git clone → yarn → npm start
浏览器打开 http://localhost:3001/，按提示完成一键初始化
默认账号：admin / ddit@1234
03
做第一个模块
1. 下载 Excel 模板（在「敏捷开发 - 系统构建」模块）
2. 填好 4 个 Sheet：表 → 字段 → 模块 → 菜单
3. 上传 Excel，平台自动构建出可运行的模块
4. 在左侧菜单点击进入你刚建的页面

06 · 你的第一个模块能长什么样

拿最常见的 m1. 数据列表 + 采集 举例。你只需要在 Excel 里写清楚：

  • 表：表名、主键、字段名、数据类型、是否必填
  • 字段：每个字段的中文名、列表里要不要显示、表单里要不要采集、用什么控件
  • 模块：列表宽度、表单布局、工具栏按钮
  • 菜单：菜单路径、组件

平台就自动生成这样一个完整页面：

  • ✅ 列表：筛选、排序、分页、列设置、勾选导出、码表转换、统计行
  • ✅ 新建 / 编辑表单：15+ 种输入控件（Input、Select、DatePicker、Upload、RichTextEditor ……）、20+ 种校验规则（必填、长度、范围、正则、自定义方法）
  • ✅ 默认操作列：编辑、删除、详情
  • ✅ 工具栏：新增、批量删除、导入、导出，以及维度表统计、图表统计、视图设置等高阶能力按钮
  • ✅ 列表视图：可保存列顺序、冻结列、隐藏列，下次自动恢复
👉 预期：从打开 Excel 到能跑通第一个模块，熟练的话 5 分钟内能完成。

07 · 几个常见的「踩坑提醒」

  1. 不要先想 UI，先想数据模型。表结构 + 字段定下来之后，UI 是顺带产出的。把字段定义写好，后续维护成本会下降一个量级。
  2. 媒体类型资源请直接用平台提供的「媒体管理」。视频预览、图片预览都是现成的，不要自己造轮子。
  3. 重要数据更新建议走「导出 → 修改 → 导入」路径，而不是直接在 Excel 里改完再重新导入整个文件。这样出问题可以回滚。
  4. 构建前打开「前端预校验」。可以提前发现字段不匹配、菜单路径错误等问题。

我能做什么？

一、不编码，能完成哪些页面和功能？

无编码，仅编写Excel模版文件，并通过敏捷开发平台进行模块构建，即可以完成下列类型页面及模块的搭建，可供需求/设计、开发人员使用。

需求/设计人员：对接客户需求，迅速产出原型图，减少原型图设计时间。并同步生成部分设计文档，规避繁琐工作。
开发人员：初始化系统搭建，基础模块搭建，同步完成数据库设计。

二、开发者进阶

1. 添加自定义按钮

  • 配置工具栏自定义按钮 需要开发
  • 配置列表列自定义按钮 需要开发

2. 对列表的自定义开发

  • 设置操作列是否可用 handle_columns disabled
  • 单元格个性化渲染 columnsRender
  • 行单击/双击事件 gridOnRowClick/DoubleClick
  • 数据删除前后处理 beforeDelete/afterDeletionFailure
  • 数据加载后处理 afterReload

3. 对表单采集生命周期的自定义开发

  • 新建前 initAddForm
  • 编辑前 initEditForm
  • 提交前 formBeforeSubmit
  • 保存/删除成功后 afterFormSaveSuccess/DeleteSuccess

4. 对表单采集项的自定义开发

  • 自定义表单项校验 validator
  • 自定义表单项事件 OnChange/OnBlur/OnFocus

5. 默认接口扩展

数据的增删查改、导入、导出接口可采用默认，也可自定义接口。
